## Summary

The game is no longer one file. `index.html` went from 4,331 lines to 343: the markup, the styles, the classic scripts and
one module tag. The engine is 30 modules in `src/` of 38 to 439 lines, next to the five pure modules from phase 1. Every
move was a move: 32 commits, one module each, with `npm test` and five seeded rides identical after every one. The intro
shots now pose the rider through `W.rider` and never touch `bike.children` or `bike.userData`. The dogs are a property of
a shot. The node render path has its own module and stays opt-in. A1's typing step is in: `npm run types` runs `tsc` on
the data types and the pure modules, inside `npm run validate`.

Unchanged from phase 1, now with `// @ts-check`: `tasks.js` 30, `reading.js` 22, `lamp.js` 16, `forks.js` 37, `voice.js`
15. New: `types.js` 51 (JSDoc types only, never loaded by the game). `main.js` 37. Total in `src/`: 4,664 lines.

How it is wired, and why:
- **Top-down, so nothing runs in a new order.** The random draws (`Math.random` paints textures at load), the scene objects
  and their ids are made in the order the code runs. Each module was cut from the top of what was left, so the modules run
  in the old order. Three blocks moved earlier because they only declare functions or create nothing (the model helpers
  and the loader, `pictogram`, the node post chain).
- **Imports.** A module imports from earlier modules directly and from later modules through `main.js`. It also imports
  the module before it. With top-level `await` in `engine.js`, `render.js` and `loop.js`, a module that did not would run
  early. The import lists were generated by a scope-aware pass over each module, so no name is missing.
- **Writes across modules.** An imported binding is read-only, so a variable written by another module got a setter next to
  it: `setL`, `setLaneX`, `setSpeeds` (state), `setTownId`, `setTownStyle` (furniture), `setHills`, `setHillPhase`,
  `setBehind` (road), `setDPR` (render), `setMSAA` (render-nodes), `setToastT` (hud), `setIntroSeen` (intro),
  `setCineFrozen` (cine), `setLampHinted` (flow), `setFaceState`, `setRackGhost` (rider). Each write site became one call.
  Four declarations moved to the module that writes them: `LANE_X` to state, `audioCtx` to audio, `MIST_Q` to scenery, the
  frame counters to loop, and `townId` up to the town-look block.
- **The node path.** `buildNodePost` takes the chain it replaces and returns the new one with its passes, and `render.js`
  keeps them through `nodePost()`. Those are the only lines that changed inside a moved function.
- **The hooks.** All `window.NR*` hooks are in `debug.js`, which runs before the boot. Three stay with what they show:
  `NRW` in `cine.js` (towns3d/nijmegen.js reads `W.NODE` through it while it builds), `NRmapBike` on its line in `map.js`,
  `NRTK` inside `townKit` in `scenery.js`.
- **Tools.** `qa/check-versions.mjs` now checks and bumps the imports in `src/*.js` too (a module loaded under two URLs
  would run twice); it skips block comments, so the JSDoc `import('./types.js')` stays bare for `tsc`.
  `qa/voice-batch.mjs` reads the fallback panels and the `speak('...')` lines from `src/` too; `voice/lines.json` came out
  byte for byte the same.

Where it differs from A1's list: the WebGL post chain stays in `render.js` (it shares the renderer and the passes with the
node path; only the node path is its own module, so there is no `render-webgl.js`). The engine half of the forks is in
`plan.js` (placement) and `flow.js` (`resolveFork`), so `forks.js` stays pure and importable in Node. There is no `save.js`
yet: stars and scores are in `state.js` until phase 4 builds the save object. The world is nine modules instead of one
`world.js`.

## 2. The rider API

In `src/rider.js` (https://github.com/SScleves/NachTrit/blob/dt/split/src/rider.js), on the shot handle as `W.rider`,
documented in `intro3d/README.md` (https://github.com/SScleves/NachTrit/blob/dt/split/intro3d/README.md):

| Call | What it does |
|---|---|
| `obj` | his group (bike and rider): place it, hang a bubble on it, put it in a rig (`W.bike` is the same object) |
| `head` | the look target; `restore()` squares it |
| `pose('ride')` | on the bike, as the game has him |
| `pose('seated', { floor, skin })` | off the bike: bike, lamp and riding limbs hidden, torso and head shown, legs bent to `floor`, hands in his lap |
| `pose('standing', { floor, skin })` | off the bike, standing, arms down |
| `pose('hidden')` | nothing of him or the bike shows; he stays where the game keeps him and his lamp still lights |
| `show(on)` | all of him; the game puts his lamp's light out while he is not shown |
| `showBike(on)` | the bike, lens, halo, tail light and beam, not him (primitives and the model's `frame`, wheels and crank) |
| `showLamp(on)`, `lens`, `halo` | the headlamp's lens and halo, and where they sit |
| `showDogs(on)` | the two dogs |
| `coat(material)` | his coat in another material; `null` gives the game's back |
| `restore()` | all of it back; `cineEnd` calls it after every shot's own `dispose` |

The shots: 9 sits with `pose('seated', { floor: FLOOR, skin })` and `coat(shirt)`, built by the same limb code that was in
the shot. 10 uses `pose('hidden')`. 2 and 13 use `coat`, `showLamp`, `head`, `lens`, `halo` and `restore`. 8 turns `head`.
11 and 14 only place bubbles on `W.bike`. Nothing under `intro3d/` reads `bike.children` or `bike.userData` any more.

The dogs: `cineBegin` shows them when the shot says `dogs: true`. Shots 8 and 14 say so. The title's 3D shot and the level
cards say so as well, because the old rule ("any shot object") gave them the dogs, and the level cards are rides.

`standing` and `showBike(false)` are not used by any shot yet. I rendered them on shot 14 to check they work
(`/home/santi/dutch-arcade-wt/split/qa/out/dt-split/poses`): standing is plain primitives, a torso on two straight legs,
fine as a base but worth an art pass before a shot uses it. With `?post=0`, the frame after `restore()` equals the frame
before any pose except his head, which `restore()` turns back to straight ahead.

## Open

- `pose('standing')` is plain and unused; give it an art pass when the ending (phase 5) needs it.
- The engine modules are not type-checked. `tsc` checks the files that opt in (`// @ts-check`): the pure modules and
  `types.js`. Turning it on for an engine module means annotating its THREE and DOM use; do it module by module.
- From phase 1, still open: `qa/readbot.js` keeps its own copy of the budget and `qa/run.mjs` its own autopilot.
- `typescript@5` is a new dev dependency (for `tsc` only; the game never loads it). CI installs it with `npm ci`.
- Level 12 can pass 600 draw calls on some loads (known since phase 0, not from this branch).
