# How NachTrit was built: stack, process, every tool, how to test

Written on 27 October 2026 by the Opus 5.5 DT agent at the end of its session (24 to 27 October 2026). What is left
to do is in `NEXT-STEPS.md` in this folder. The working rules for any agent are in `README.md` in this folder.

## 1. The game

NachTrit is a browser horror comedy lane runner that teaches Netherlands Dutch. A man on an omafiets rides home at
night through 13 Dutch towns. The dead stand in the road and ask him things. A right Dutch answer brings a word back.

## 2. Languages and frameworks

| Layer | What is used | Where |
|---|---|---|
| Markup and style | HTML5 and CSS3. No UI framework. | `index.html` |
| Code | JavaScript (ES2020). One ES module inside `index.html` (about 3,700 lines) plus classic scripts loaded before it. | `index.html`, `*.js` |
| 3D | Three.js 0.152.2 (r152) from the jsDelivr CDN through an import map, on WebGL. Add-ons: `EffectComposer`, `RenderPass`, `ShaderPass`, `UnrealBloomPass`, `TexturePass`. | `index.html` |
| 2D | Canvas 2D: the pixel paintings, the map, signs, labels and every texture are drawn in code. No image files are loaded by the game. | `intro/`, `map-art.js`, `index.html` |
| Sound and voice | Web Audio API for sounds. Web Speech API (`speechSynthesis`) speaks the Dutch. | `index.html` |
| Saving | `localStorage`, for example `nachtrit.progress` (stars), `nachtrit.scores`, `nachtrit.intro` (intro seen), `nachtrit.unlock` (all towns open). | `index.html` |
| Hosting | GitHub Pages serves the `main` branch as static files (`.nojekyll`). Files are cached by browsers for 10 minutes (`Cache-Control: max-age=600`). | repo root |
| Tests | Node.js with Playwright driving headless Chrome or Chromium. Python 3 `http.server` as a local server that turns caching off. | `qa/`, `qa/dt/`, `serve.py` |

There is no build step and no bundler. The browser runs the files as they are in the repo. Unity and Unreal were
installed in VS Code by Santi but were not used: the game is a web page and stays one.

## 3. Files and the order they load

`index.html` loads classic scripts first, in this order, then the import map, then its module:

1. `data.js`, `levels.js`, `content/*.js`, `fares.js`, `map-art.js`, `content/extra.js`: sentences, levels, towns, fares, the map painter.
2. `intro/art.js`, `intro/panel-1.js` to `panel-14.js`, `intro/scene-*.js`: the pixel paintings, on `window.NRART`.
3. `intro3d/shot-1.js` to `shot-14.js`: the 3D intro shots, on `window.NRCINE`.
4. `towns3d/<town>.js` for the 13 towns: each town's 3D look, on `window.NRTOWNS3D`.

The module then builds the game and reads those globals. A new shot or town is a new file plus one script tag.

## 4. How the main parts work

**Loop and modes.** The state object `S` (`window.NR`) has a mode: `start`, `intro`, `ride`, `dying` or `cine`.
`loop()` runs every frame: `cineTick(dt)` in `cine` mode, `update(dt)` while playing, then `render()` through the
post pipeline (the scene renders into `sceneRT`, the composer reads it).

**Road and towns.** `buildScenery(theme)` builds the street from one of the themes `street`, `gracht`, `shops`,
`square`, `nightshop`, `dyke`, `polder`. The town file adds what makes the place recognisable: the sky (stars, the
Milky Way, an aurora band, glows), the light tint, the road surface (klinkers, cobbles, slabs), hills, how the dead
dress, the lamps, a skyline, landmarks. Zeeland rides on the dikes, Texel has the open sky and the aurora, Urk has its
dress, Nijmegen and Maastricht have hills, Rotterdam has its skyline, Amsterdam has the neon. The spec with sources is
`TOWNS-IDENTITY.md` and `research/`. The guide is `towns3d/README.md`.

**The dead and the passengers.** `zombieParts` and `ghostFigure` in `index.html`: smooth bony dead in rags,
passengers with coats, faces and hair, each with a near and a far version to keep the draw calls down.

**Intro.** Fourteen panels. Each panel has a pixel painting and a 3D shot. The shot plays when it can, the painting
is the fallback. The first run plays eight panels, the link on the start screen plays all fourteen.

**Cine framework.** A shot is an object `{ hold, build(W), update(W, t, dt), dispose(W) }`. `W` (`window.NRW`) is the
world handle: `stage`, `cam`, `drift`, `add`, `say`, `title`, `hide`, `band` and the game's own builders.
`cineBegin`, `cineTick`, `cineFrame` and `cineEnd` in `index.html` run it, letterbox it and clean up after it.
The guide with every call is `intro3d/README.md`.

**Level cards.** `levelCard(lv, k)` makes a 3D shot of the level's own town before each level, seeded by the level id.

**Title screen.** `startArt.on3d()` holds the first beat of intro shot 1 (the mills of Kinderdijk at night) behind the
title, so pressing Start cuts into the same shot. The painting remains as the fallback.

**Map and unlock.** `map-art.js` paints the Netherlands as a diorama with the towns on it. Towns open in order;
`?unlock=1` opens all of them on that device.

**Content.** Levels are data. `README.md` in this folder, section 2, explains the item kinds, the generated bundles and
the validators.

### How the work was done

1. **Read the brief.** Santi's files in this folder: `README.md`, `BACKLOG.md`, `HANDOVER.md`, `NOTES.md`,
   `FIRST-FIVE-MINUTES.md`, `SANTI-MESSAGES.md`, `concept-art/` and `reference/`. The concept art is the visual target;
   the agent looked at every image.
2. **Study.** The repos Santi pointed to (`REFERENCE-REPOS.md`, https://github.com/IdoCohen560/claude-unity-game-studio,
   https://github.com/lappemic/awesome-ai-built-games) were read through the GitHub MCP server and web fetch. For the
      towns, four research agents searched the web and wrote sourced notes, compiled into `TOWNS-IDENTITY.md` and
   `research/`.
3. **Build the engine first, then fan out.** The main agent wrote the shared engines itself (the cine framework, the
   town engine, the level cards, the title screen). The per-shot and per-town work went to subagents in parallel.
   Each subagent got its own git worktree, its own branch `dt/<topic>`, its own local server port, a brief
   (`briefs/shot-agent-brief.md`, `briefs/town-agent-brief.md`) and files no other agent touched (one shot file, or
   one or two town files). That kept `index.html`, the conflict hotspot, in one pair of hands.
4. **Review on the real GPU.** Every result was rendered on the laptop's Intel Iris Xe (headless Chrome with ANGLE on
   Direct3D 11), looked at as screenshots and contact sheets, measured (draw calls, triangles, frame time, brightness)
   and run through the flow checks. Gaps the agents found in the framework were fixed by the main agent.
5. **Combine and test on top of main.** Agent branches were merged into one combined branch, tested again on top of
   the current `main`, then pushed.
6. **Ship.** Santi opens and merges every pull request himself. GitHub Pages publishes `main` in about a minute.
   Browsers keep the old files for up to 10 minutes, so check with Ctrl+F5 on a laptop or a private tab on a phone.

## 7. How to test

### Set up once

```
git clone https://github.com/SScleves/NachTrit.git
cd NachTrit
npm ci
npx playwright install chromium
```

`npx playwright install chromium` is optional when Chrome is installed: then pass `--browser chrome` to the `qa/dt`
scripts that take it, or set `NR_CHANNEL=chrome` for the repo harness.

### Serve the game

Windows: `py qa/dt/serve-local.py . 8765`. Mac or Linux: `python3 serve.py 8765`. Open http://127.0.0.1:8765/

### The checks

| Command | What passes |
|---|---|
| `node qa/validate-content.mjs` | Ends with `0 errors, 0 warnings`. Run after any content change, after `node qa/build-content.mjs`. |
| `node qa/run.mjs 1` (PowerShell: `$env:NR_CHANNEL='chrome'; node qa/run.mjs 1`) | The repo harness plays level 1; the report shows `errors: 0`. Also `intro`, `endless`, `all`, or a level id. |
| `node qa/dt/start3d.mjs` | Title screen in 3D, Start opens on intro panel 1, map, a ride and the replay link are clean, `errors 0`. |
| `node qa/dt/intro-all.mjs` | Every intro panel prints `3D`, the ride afterwards is clean, `errors 0`. |
| `node qa/dt/card-check.mjs http://127.0.0.1:8765/index.html qa/out/cards 1,75,129` | The cards before those levels play in 3D, `errors 0`. |
| `node qa/dt/cine-flow.mjs` | Panel 13 to shot 14 to the map to level 1 at three screen sizes, nothing of the shot leaks. |
| `node qa/dt/unlock-check.mjs http://127.0.0.1:8765/index.html nijmegen,amsterdam` | Unlock and lock work, the towns ride. |
| `node qa/dt/mission-fit.mjs http://127.0.0.1:8765/index.html 390 844 1,115,130 qa/out/mission` | The Ride button is on screen on a phone. |
| `node qa/dt/shoot.mjs --browser chrome --out qa/out/look L1="level=1&shot=7&lane=1"` | A frame plus draw calls, triangles, frame time and brightness. Keep draw calls under about 600. |
| `node qa/dt/grid.mjs qa/out/look qa/out/look-grid.png 3 420` | A contact sheet to look at many frames at once. |

Test at three sizes: laptop 1280 x 800, phone upright 390 x 844, phone on its side 844 x 390. Look at the frames;
the numbers do not show whether a town looks right.

### Debug links

`?unlock=1`, `?map=<town>`, `?level=<id>&shot=<seconds>&lane=1` (ride and hold a frame), `?town=<id>&theme=<key>`
(dress a level as another town), `&hillphase=<metres>`, `?cine=<panel>` (play the intro from a panel),
`?cine=<panel>&t=<seconds>` (hold a 3D shot), `?intro=1` (as a first run).

## 8. Traps met in this session

- A shot that measures the screen from a hidden element gets zeros. Shots read `W.band()`, which knows where they play.
- One key press can reach two handlers. Space on the title opened the intro and skipped panel 1 in the same press;
  the title's handler now stops the event.
- Right after a merge, a reload can mix the new `index.html` with old cached shot files, and a panel then shows its
  painting. Wait 10 minutes or force the reload. `NEXT-STEPS.md` has the lasting fix.
- PowerShell variable names ignore case: `$f` overwrites `$F`.
- git writes progress to stderr, so PowerShell shows an error on a push that worked. Check the last line.
- The repo is LF without a BOM. Tools on Windows write CRLF; convert before committing.
- Subagents fail on large image requests. Tell them to look at two images at a time and to use contact sheets.
- `git worktree remove` can leave the `node_modules` junction behind; remove it with `cmd /c rmdir`.
- Three.js r152 lights fade as `(1 - d / distance) ^ decay`. Intensities from newer examples come out far too bright.
